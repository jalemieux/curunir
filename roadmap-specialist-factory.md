# Specialist Factory — Roadmap

## Core Insight

Curunir is a platform for specialized bots. Specialization = different `identity.md` + different `skills/` + different secrets. Same agent loop, different configuration.

## Example Specialists

- **Executive Assistant** — calendars, email, Google Workspace via gog CLI
- **Financial Analyst** — FRED, Yahoo Finance, Polygon.io APIs, deep-research
- **Marketer** — HubSpot, Marketo, SFDC MCPs

## Architecture

### Deployment Model

Each specialist runs as its own standalone Docker container (no docker-compose orchestration). The persona config determines what gets baked into the image.

### What Varies Per Persona

- `context/identity.md` — personality, domain expertise, tone
- `skills/` — which SKILL.md directories are included
- Secrets/env vars — API keys for the tools that persona needs
- System deps in Dockerfile (rare — most tools are API-based via curl)

### What Stays the Same (the curunir platform)

- Agent loop (`run.py`, `src/agent.py`, channels, queues)
- `src/skills.py` — skill discovery and loading
- Tool infrastructure (`src/tools/`)
- Memory system
- Docker base image and entrypoint

### Directory Structure

```
curunir/
  src/                          # shared platform
  skills/                       # shared skill registry
    web-search/SKILL.md
    deep-research/SKILL.md
    email-send/SKILL.md
    fred-api/SKILL.md           # generated by factory
    polygon-data/SKILL.md       # generated by factory

  personas/
    financial-analyst/
      persona.yaml              # metadata, skill list, required env vars
      identity.md               # generated personality + expertise

  Dockerfile                    # base image
```

### Persona Definition Format

```yaml
# personas/financial-analyst/persona.yaml
name: financial-analyst
identity: personas/financial-analyst/identity.md
skills:
  - deep-research
  - web-search
  - fred-api
  - polygon-data
env:
  - FRED_API_KEY
  - POLYGON_API_KEY
```

### Build & Run

```bash
curunir build financial-analyst   # builds Docker image from base + persona config
curunir run financial-analyst     # runs standalone container with env vars
```

Under the hood: reads persona.yaml, copies the right identity.md and skills into the image, builds it.

## The Factory — LLM-Assisted Skill & Persona Generation

The factory is a Claude Code skill (`.claude/commands/new-specialist`) — a dev-time conversational workflow that manufactures new specialists.

### Conversation Flow

**Step 1 — Define the Specialist**
- "What does this specialist do? Who is it for?"
- User describes the persona in natural language
- LLM drafts `identity.md`, user refines

**Step 2 — Inventory Skills**
- "What capabilities does it need?"
- LLM proposes a skill list based on the description
- Splits into: existing skills (reuse from registry) vs. new skills needed
- User approves/adjusts

**Step 3 — Generate New Skills** (loop per skill)
- LLM asks: "What API/service does this use? Do you have docs or an API key?"
- Fetches API docs if given a URL
- Generates SKILL.md following existing pattern (frontmatter + instructions + curl/bash examples)
- If the skill needs a new Python tool (not just bash/curl), generates schema + executor
- User reviews each skill before moving on

**Step 4 — Generate Persona Config**
- Produces `persona.yaml` (skill list, env vars)
- Produces `identity.md`
- Lists required secrets

**Step 5 — Build & Verify**
- Builds Docker image
- Runs smoke test (agent loads, sees its skills)

### Design Decisions

- **Skills are bash/curl-first.** Most API integrations are just "teach the LLM how to call an API via curl in a SKILL.md." New Python tools only needed for capabilities that can't be done via bash.
- **Factory is a dev-time tool** (Claude Code skill), not a runtime curunir skill. Self-manufacturing agents is a later evolution.
- **Bake, don't mount.** Skills + identity baked into Docker image at build time for reproducibility. Each specialist image is self-contained.
- **Shared skill registry.** `skills/` is the shared pool. Personas reference skills by name. Avoids drift.

## Implementation Sequence

1. **Shared skill registry** — refactor skills into a registry that personas reference
2. **Persona definition format** — `persona.yaml` schema
3. **Build/run scripts** — `curunir build <name>` / `curunir run <name>`
4. **Factory skill** — Claude Code skill for LLM-assisted persona + skill generation
5. **Self-manufacturing** (future) — curunir agents that can extend their own capabilities
